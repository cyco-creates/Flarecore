# Fresh-eyes audit, 2026-09-06

Base: `88536c5`. Method: the engine, schema, render node, element math,
detector, occlusion, HTTP routes, library and forge were read in full by one
reviewer; three further reviewers covered the tracking subsystem, JS-vs-Python
parity, and tests/packaging/docs in parallel. Every finding marked **verified**
below was reproduced by running code or confirmed at the cited lines; findings
marked *reported* come from a reviewer and were not re-run.

**Verdict.** The engine and the product thinking are strong -- linear-light
HDR, identity-stable seeding, energy-conserving anti-aliasing, the
track-the-camera insight -- and the reasoning is unusually well documented.
The risk sits in two places: the newest code (off-frame lights, `follow`,
scene anchoring) had bugs the tests could not reach and that had never been
run on the owner's server; and the node contract is duplicated across Python
and JS with nothing pinning it, which is the machine that produced today's
default-value bugs and will keep producing them.

Three of the bugs below are **fixed in this round** (marked FIXED) with tests
that place a light outside the frame -- the first tests in the suite to do
so. Everything else is open.

## 2. The structural cause

Bugs 6, 9, 12, 13 and the JS `track_max_jump` slider max (0.5 vs the node's
1.0) are one bug: about twenty tables live in both Python and JS, and **no
test executes a single line of JS**. `triggerFactor` and `samplePath` parity
was verified by hand in a browser once and never pinned; the parity table is
clean today only because recent rounds were careful.

Two changes end the class:

- **Serve the contract from Python.** The JS already fetches
  `/flarecore/elements` and `/flarecore/prompt_bank`. Add `/flarecore/schema`
  returning defaults, bounds, `ELEMENT_TYPE_OVERRIDES`, `POSITION_MODES` and
  `MODE_DEFAULTS` -- the last is pure data and belongs beside `INPUT_TYPES`.
  The JS consumes it. One source of truth.
- **Pin what cannot be served.** A test asserting INPUT_TYPES defaults ==
  the `render()` signature == `_resolve_lights()`; and a small Node runner
  for the two pure JS functions against the Python reference values (the
  `sed 's|^import .*|//|'` trick already gets the module to parse).

## 3. Distribution blockers

- **User data lives inside the package.** `/flarecore/save_preset` writes to
  `presets/`, `FlareElementSave` to `elements/`. A Registry reinstall or a
  Manager "fix" wipes every saved look and forged texture. User writes belong
  in the ComfyUI user directory; the shipped set stays read-only in the pack.
- No `requirements.txt` (Manager installs from it, not from pyproject).
  `pyproject.toml` omits **Pillow**, a hard top-level import in
  `nodes/library.py` and `nodes/elements_lab.py`. `PublisherId` and `Icon` are
  empty; `version` is a static 0.1.0.
- Both shipped workflows need **VideoHelperSuite** and **controlnet_aux**
  (Depth Anything). Undocumented; the trigger lab claims "nothing to load".
- README: line 4 still says "no textures"; the position-mode list omits
  `detect_with_manual_offset`; the `occlusion_radius` pixel figures are wrong
  (the radius is a fraction of *height*; 0.02 -> 0.08 is 4x, not 2.3x).
- `presets/specimen_all_elements.json` has 7 of the 9 element types (no
  `orbs`, no `texture`).

## 4. Performance -- where the time really goes

**121 ms for one 960x540 frame of `cine_blue` on an RTX 5090.** That is not
the GPU. It is Python dispatch of full-frame tensor ops per light x element x
count-instance x dispersion sample, plus inner Python loops in `orbs`, `glint`
and `streak` that issue up to 200 / 256 / 32 full-frame ops each. Bounding-box
evaluation (already on the list) is one lever. The others, by payoff over
risk:

1. **Cache static fields per chunk.** Screen-space and `fill_frame` lens
   plates render *identically* every frame; only the mask factor and the
   light's weight change. Near-free for dirt-heavy presets.
2. **Batch one element across a chunk's frames.** The field function does not
   care that the transform differs per frame: stack a (B, H, W) grid and
   launch once.
3. **Vectorise the inner loops** -- orbs, glint, streak, and the per-light
   glow-mask loop in `render()`.
4. **Kill the syncs.** The tracking reviewer counted tens of thousands of
   `.item()`/`float()` calls per clip in `scene_motion`, `good_features`,
   `detect` and `feature_track`; `estimate_motion` re-runs once per track id;
   the clip is sRGB-decoded three to four times.

A "compile the preset into a flat instance list, then render" step makes 1-3
local changes instead of surgery on `_accumulate_element` (fifteen parameters
and growing), and lets the preview route share the path.

fp16 offers nothing here: measured slower and banded (bug 8).

## 5. Realism -- against the stated goal

- **Scene-wide halation / veiling glare.** `out += k * blur(plate_linear,
  sigma)`: the flare of *every* bright pixel, not only the tracked light.
  About five lines with `blur_depth`. This is the largest missing film-look
  lever; `film_halation` and `cheap_zoom_haze` approximate it with elements
  pinned to the light point.
- **Use source size.** `detect.py` already computes `energy`; the engine
  ignores it. A large soft sun should throw bigger, softer ghosts than a
  pinpoint.
- **Lens dirt lit by every light.** `render_stack` weights screen-space
  elements by the *strongest* light only, while the reveal mask already maxes
  over all of them. Two headlights light the dirt from one.
- An `fps` input (VideoHelperSuite provides it) so flicker, hold and fade
  mean the same thing at 24 and 60.

## 6. Test gaps that let the above through

No JS executed; no HTTP route tested; no fp16; every test frame is even-sized;
portrait never goes through FlareRender; the CUDA / VRAM-chunking path never
runs; the "all elements" specimen renders 7 of 9 types. And the pattern behind
bugs 1 and 4: until this round nothing placed a light **outside** [0, 1],
even though the widget range is -1..2 and `follow` is built on it. When a
feature widens a domain, the first test to write is the one at the new edge.
